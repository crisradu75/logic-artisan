Trigger: real ambiguity. The brief says the text cites the two shared sources and never copies them, yet the file it ships must be readable by an agent in a consuming repo, where a plugin path does not resolve outside a skill.

## Decisions

- **Render at write time, from sources made portable.** The reference holds only what the two sources lack (model by task, the quality floor, the framing) plus two include markers. `cla-setup` builds the consumer file from the reference with the two sources inlined whole, so the table and the cost rules still exist once in the plugin. The sources are reworded so they read correctly with no plugin installed (no plugin path, no chain or skill names, the prose-dominant rule stated as "files that steer an agent"). Rejected: copy them into the reference (breaks the single-source guard); write only a pointer into the consumer file (an agent outside a skill cannot resolve the plugin path, so it reads nothing).
- **Explicit extraction markers.** `model-routing.md` carries a begin and an end comment around the heading through the Round 2 paragraph. The block extracts between them, so a footnote added after the table still extracts and the Artifact-class override stays out. Rejected: extract "to the table" (a later paragraph silently drops or leaks).
- **Replace on every run, no prompt.** The file is plugin-owned and is meant to track the plugin. The block cannot tell a hand edit from a plugin upgrade, so it reports `replaced` when existing content differed from the fresh render, `created` when absent, `unchanged` otherwise. The file is committed in the consumer repo, so an upgrade changing a tracked file is by design. Rejected: ask first (a stale copy defeats the file); merge into the owner's edits (ownership stays whole).
- **Line endings.** Sources and the existing file are read through `tr -d '\r'`, so a CRLF checkout and an LF one render the same bytes and compare `unchanged`.
- **Plugin root.** `${CLAUDE_PLUGIN_ROOT}` is substituted in the SKILL.md text, not an environment variable. The block carries a guard like the existing `ROOT` guards, and the test substitutes the plugin root as a literal and runs the block with only `ROOT` set.
- **Write step is a bash block in `SKILL.md`**, regex-extractable the way the existing cla-setup tests in `tests/consistency/` extract theirs, so the outcomes are testable without a model.
