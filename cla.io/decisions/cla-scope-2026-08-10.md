# Decision — CLA scope and shape

**Topic (inferred):** what CLA should actually contain, given that 82% of the plugin is machinery
around 18% instructions. Prompted by the observation that CLA looks nothing like a standard
marketplace plugin and carries a lot of maintenance for edge-case protection.

Companion to `cla-propagation-2026-08-09.md`, which decided *how* CLA is distributed. This decides
*what gets distributed*, and Q7 below re-orders the two.

## The measurements this rests on

Plugin composition (`.claude/plugins/cla/`, before any change):

| Category | Files | Lines | Share |
|---|---|---|---|
| SKILL.md prose | 18 | 2,499 | 8% |
| `references/*.md` prose | 56 | 3,573 | 11% |
| skill scripts | 64 | 7,514 | 23% |
| skill tests | 78 | 8,115 | 25% |
| hook code | 18 | 4,687 | 14% |
| hook tests | 46 | 6,244 | 19% |
| agents + output-style | 3 | 249 | 1% |

Official marketplace plugins doing comparable work, for scale: `code-review` 549 lines,
`feature-dev` 878, `pr-review-toolkit` 1,261, `plugin-dev` 21,857 (mostly reference docs).
**None of the four ships a single hook.**

Other figures gathered during the session:

- **2,496 lines** of the hook layer (1,200 code + 1,296 tests) is dispatcher plumbing, not hooks.
- **`block-direct-push-to-main` is 1,171 lines** — the largest hook, enforcing what GitHub
  enforces natively.
- **`block-cd-in-bash` is 70 lines with no test file** — and is the only hook observed firing on a
  real violation during this session.
- Retro ledgers hold **194 records across all five repos**, distributed as: `spec-to-pr` 132,
  `codify` 43, `multi-pr` 9, `multi-spec` 5, `multi-lite` 4, `project-review` 1. Only the first two
  have a retro skill that reads them.
- Five near-identical `log_run.py` copies total **856 lines**; the `consistency-checks` scope exists
  solely to police drift between them.
- The three `multi-*` skills total **2,126 lines** for 18 recorded runs.
- `spec-to-pr` (5,606 lines, the most-used skill) is internally 27% prose, 30% scripts, 39% tests.
- `shape-decision`, which ran this session, is **107 lines**. `lite-pr` is **186**.

Context that bears on all of it: the guard layer's benefit is **unmeasured, not disproven** — a
global `alias cla="claude --permission-mode auto"` in `~/.bashrc` (found and removed 2026-08-09)
meant the plugin was largely not loading across repos.

## Decisions

| # | Question | Chosen | Rationale |
|---|---|---|---|
| 1 | Guard-hook layer (13 hooks, 10,931 lines) | **Replace with real mechanisms where one exists; keep only hooks with no equivalent and demonstrated value; delete the rest** | Converts heuristic shell-string parsing into guarantees git itself enforces — deletes a defect class instead of one bypass at a time |
| 2 | Retro / self-observation loop | **Delete the four unconsumed ledgers and their `log_run` copies; consolidate the two real ones into a shared module** | A ledger with no consumer is exhaust, not data; the duplication only exists to work around a constraint a shared module removes |
| 3 | `multi-*` family (2,126 lines, 18 runs) | **Keep all three skills** | The batch entry points are worth having as named commands |
| 4 | Helper scripts (~9,400 lines with tests) | **Audit each against "does this do something a direct command plus a sentence cannot do reliably?" — delete failures with their tests** | Keeps determinism where determinism is the point, stops paying for it where it isn't |
| 5 | Test policy | **Keep tests only where something can silently break; drop prose content-locks and wrapper restatements** | Targets the failure mode tests can catch and stops paying for the one they demonstrably can't |
| 6 | What stops regrowth | **Nothing formal — judgment at review time** | No new mechanism; this session shows judgment can cut when the numbers are visible |
| 7 | Order vs the migration | **Trim in logic-artisan first, then migrate the reduced core** | Migration cost scales with what's migrated; cutting first avoids deduping overlays across four repos for things about to be deleted |

### Interactions worth holding

- **Q2 + Q3**: the three `multi-*` skills survive, but their ledgers and `log_run` copies do not.
  The skills keep working; they stop recording.
- **Q1 + propagation §1.2**: if `warn-smoke-test-drift` and `warn-lint-on-edit` are cut, their
  `.local.md` overlays never need relocating, and that section of the migration plan shrinks.
- **Q7 + propagation Q9**: the consumer pilot still comes first among consumers — it just comes
  after the trim rather than before it.

## The honest caveat

Four of these seven (Q1, Q2, Q4, Q5) are **per-item audits**, and Q6 declines any mechanism to hold
the result. That is coherent only if the audits are actually performed rather than approximated —
the same judgment that produced +94% in 18 days is now the only thing carrying the reduction.
Worth revisiting Q6 if the trim stalls partway.

## Open questions

1. **Which hooks clear the "demonstrated value" bar.** Q1 named no list because the firing data does
   not exist — no hook records whether it ever caught a real violation. Grepping session transcripts
   across the four consuming repos for block/warn output would produce that number cheaply, and it
   is the input Q1 is missing.
2. **Where the replacement push-to-main protection lives.** A git `pre-push` hook (works everywhere,
   sees the refspec after git parses it) versus GitHub branch protection (unbypassable, but may
   require a paid plan on private repos — unverified).

## Why this matters, and what's next

The propagation decision stops divergence. This one decides how much there is to keep in sync in the
first place — and the two compound: a smaller core makes the marketplace migration substantially
cheaper, which is why Q7 puts the trim first.

Natural next step: settle open question 1 (measure hook firings), then re-plan the trim as a
sequence of changes — Q1's guard replacement is the largest and least reversible, so it belongs
behind that measurement rather than in front of it. The parked migration plan
(`cla-propagation-2026-08-09.md` and its six Phase-1 tasks) resumes once the trim lands.
