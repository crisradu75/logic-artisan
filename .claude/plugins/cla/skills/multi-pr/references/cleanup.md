# cleanup — Phase 4 final cleanup pass (full mechanics)

Phase 4's step-by-step procedure, run once after every change in the sequence is done. `SKILL.md`'s Phase 4 stub carries the load-bearing invariant (re-running the chain-level green gate, path-scoped staging); this file carries the recipe.

1. **Verify <base-branch> is green.** This repo's own workspace-wide build/lint/test commands (see `cla.io/project-facts.md`, falling back to `references/project-context.md` if absent), plus its local-infra-dependent hard gate if any shipped change touched the tables/surfaces it covers. This is the one gate that's worth re-running at the CHAIN level even though every individual change already passed it standalone — a later change's merge can occasionally interact with an earlier one in ways neither change's own Test phase would catch alone.
2. **Prune stale remote-tracking branches:** `git fetch --prune`. `gh pr merge --delete-branch` deletes the branch on GitHub; the local `remotes/origin/feature/...` ref doesn't disappear on its own.
3. **Remove leftover local branches/worktrees.** `git branch -a` and `git worktree list` should show nothing but `<base-branch>` (and any worktree the user set up for reasons outside this chain — don't touch those). If `/cla:spec-to-pr`'s own "Concurrent runs" worktree pattern was used for any change in this chain, remove that worktree now (`git worktree remove .claude/worktrees/<change>`) — the branch is already gone via `--delete-branch`.
4. **Confirm every change in the original sequence is archived.** `ls openspec/changes/` should show only `archive/` (or only the changes that were deliberately left out of scope, if the run was explicit-mode over a subset).
6. **Commit the chain-log line to `<base-branch>`.** Unlike `/cla:spec-to-pr`'s per-run line (which rides its feature PR), this record is written directly on `<base-branch>` after the last merge, so it must be committed explicitly or it lingers as a dirty working tree that trips a later resume's clean-tree expectation. After a `git_state.py --expect-branch <base-branch>` check, path-scope the add (never `-A`): `git add cla.io/retro/multi-pr-runs.jsonl` then `git commit -m "chore: multi-pr chain log"` and `git push`. (Skipped only when `CLAUDE_RETRO_DIR` points the ledger outside the repo — then there's nothing tracked to commit.)

   **If the push is blocked** (a repo's own `block-direct-push-to-main.py` or equivalent — this step's whole point is a direct commit to `<base-branch>`, so a repo whose guard has no metadata-only exception will legitimately refuse it): don't reach for `ALLOW_PUSH_TO_MAIN=1` as a routine workaround — that escape hatch is for a genuine emergency, not a scheduled housekeeping step. Instead, fall back to a small branch + PR for just the chain-log line: `git checkout -b chore/multi-pr-run-log`, commit there, push, `gh pr create`, and report the PR URL in step 7's final status as a "log PR — merge whenever" item.
7. Mark the "Final cleanup pass" task complete and report final status: which changes shipped, their PR numbers, the final `<base-branch>` commit, and confirmation that the repo's full gate (build/lint/test + any local-infra hard gate) is all green.
